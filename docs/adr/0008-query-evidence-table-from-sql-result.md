# 0008. 戰情室的表格由後端從最後一句 SQL 的結果產生，LLM 只寫摘要

## 狀態
Accepted (2026-11-15)。修正 [ADR-0002](0002-text-to-sql-architecture.md) 第 3 點。

## 背景脈絡 (Context)
ADR-0002 承諾回答是「一段自然語言摘要＋一個 Markdown 表格」，但 prompt 從未要求，Agent 有時給條列、有時一句話。如果改成在 prompt 要求 LLM 自己寫表格，數字會被 LLM 重新抄一次，可能抄錯，而老闆無從察覺。

同時，評估 (ADR-0006) 是重跑 Agent 最後一句 SQL 來判分。第一次評估發現 Agent 有時分兩句查詢、再自己心算合併：回答是對的，最後一句 SQL 卻不完整，被判錯。

## 決策 (Decision)
1. **查詢依據 (Query Evidence)**：Agent 回答完後，後端用同一套防護 (ADR-0005) 重跑最後一句 SQL，把欄位與資料列原樣送給前端（`result` 事件），前端以結構化資料渲染成表格。表格不經 LLM，也不經 `v-html`。LLM 只負責摘要。
2. **最後一句 SQL 必須單獨回答整個問題**：系統提示要求差額、比例、比較都在同一句 SQL 算好。這讓摘要和表格一致，也讓評估判分重跑的 SQL 就是使用者看到的那一句。

表格每次有查詢結果都附上（含只有一個數字時），預設展開，可收合。

### 考慮過的選項
- **在 prompt 要求 LLM 輸出 Markdown 表格**：改動最小，但數字經過 LLM 轉抄，無法保證和資料庫一致。
- **不做表格，改寫 ADR-0002**：最省事，但失去「每個數字都有依據」的透明度。

## 後果 (Consequences)
- 老闆看到的數字都能追溯到產生它的 SQL；畫面上的表格和評估判分重跑的是同一句 SQL。
- 每次回答多執行一次查詢（唯讀、有逾時與筆數上限），成本可忽略。
- 若 Agent 違反規則仍分多句計算，表格只會反映最後一句，可能和摘要對不起來；這個風險由評估集持續量測。
- SSE 前端必須能處理被切成多段送達的事件（長結果常見），已改為逐行緩衝解析。

## 修訂 (2026-11-16)：第 2 點的用詞
原用詞是「最後執行的那一句 SQL 必須單獨就能回答整個問題……因為使用者會看到這句 SQL 的結果表格」。重跑原 20 題（`backend/evaluation/results/2026-11-15_1706.md`）發現副作用：問一個總數的題目（AL-1、AL-2、CN-1），Agent 改成 `GROUP BY bl_number` 每張提單一列，還附上沒被問到的欄位。推測是「使用者會看到表格」讓 Agent 想把表格做豐富。

改為：「最後一句 SQL 的結果就是答案本身：問一個總數就只回傳那個總數，問哪一張就回傳那一張；差額、比例要在同一句裡算好……不要拆成明細，也不要加上沒被問到的欄位。」決策本身不變（仍要求同一句算好），只拿掉誘導加欄位的理由。效果用沒用過的第二組驗證題量測（ticket 10），不用原 20 題或 H 題組證明。
