# 0006. 評估集以 Agent 的 SQL 執行結果判分，不用 LLM 評審

## 狀態
Accepted (2026-11-11)

## 背景脈絡 (Context)
評估集 (Eval Set) 要量測的是：資料層（整理過的 view、資料字典）能不能幫 Agent 查對資料。判分方式必須可重現，才能比較不同對照組 (Arm) 的差異。

## 決策 (Decision)
執行 Agent 的最後一句 SQL，拿結果和標準答案 (Gold Answer) 比對：數字容許 ±0.01 誤差，集合比對時不看順序。這樣判分是確定性、可重現的；改用 LLM 評審，等於拿一個不確定的系統去評另一個不確定的系統。

每題在每個對照組各跑 3 次，跑在剛 seed 好、內容固定的獨立 SQLite 檔上。除了整體準確率，也依陷阱類型分別報告。

## 後果 (Consequences)
- 已知盲點：如果 Agent 查對了，但在自然語言摘要裡把數字寫錯，仍會被判為正確。
- 標準答案從產生器「弄髒之前」的乾淨原始資料算出，絕不從整理過的 view 查出，否則等於讓 view 自己幫自己打分數。
- 因為答案是固定的，資料也必須固定：seed 資料使用絕對日期，評估題一律寫明確月份，不使用「上個月」。
